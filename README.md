# Commander Lab

An Electron desktop Commander playtester with a four-seat manual tabletop.

For code navigation and refactoring guidance, see [code structure](docs/code-structure.md).

Rules work is tracked in the [39-deck implementation checklist](docs/commander-deck-checklist.md), with per-deck acceptance criteria, card-by-card Oracle audits, checked test evidence and remaining gaps. Ten decks currently pass their scoped audits, through Kess. See [implementation notes](docs/rules-implementation.md) for sources and verification status.

The two exact Atraxa/Jace lists supplied during playtesting have a separate [card-by-card audit](docs/playtest-deck-audit.md). That report distinguishes verified regression coverage, missing resolution handlers, and unverified interactions; neither list is currently certified fully working. Regenerate it with `npm.cmd run audit:playtest-decks`.

## Run

For friends joining the playtest, start with the [playtester setup guide](docs/playtesting.md).

Windows testing builds are distributed through [GitHub Releases](https://github.com/jtlavigne/commander-lab--2-/releases). Download the installer or portable ZIP; Node.js is not needed for these builds. Installed Windows builds support **Settings > App updates > Check for updates**, with download progress and a confirmed restart to install. Older versions need an update-enabled installer once; ZIP and source builds update manually. See [release instructions](docs/releasing.md) to build or publish a new prerelease.

With Node.js 24 installed, open this folder in a terminal and run:

```powershell
npm.cmd ci
npm.cmd start
```

`npm.cmd` works in PowerShell even when script execution is disabled. On other shells, use `npm install` and `npm start`. Electron is a development dependency; this folder is not a prebuilt Windows installer. The launcher clears an inherited `ELECTRON_RUN_AS_NODE` flag in its child process so the app also launches from Node-based development hosts.

Deck imports also load a hidden, per-player **token reserve** using Oracle text and Scryfall's related-token IDs. Supported resolving effects create fresh copies with token artwork; the reserve is never consumed or shuffled into a deck. Use **Token > Imported token reserve** for manual creation, or choose **Custom token**. Templates survive saves and game resets and remain private in multiplayer until a copy enters play. Reimport existing decks to populate their reserves. Missing token artwork is reported during import, with text templates retained where the Oracle description can be parsed. Importing templates does not automatically implement unsupported card effects.

To copy a creature or other permanent, open its arrow menu and choose **Create token copy**, then select the quantity. You can also use **Token > Copy a battlefield permanent**, including an opponent's permanent. Copies retain the source's artwork and rules text, so supported activated, triggered and static abilities work through the normal engine. Each copy has independent counters, damage and tapping state. Check **Not legendary** only when the effect specifies that exception. Existing blank Copy markers need to be recreated from their actual source; unsupported Oracle effects still require manual handling.

Auto untap / draw is saved separately for each player. In local hotseat play the checkbox follows the controlled seat; multiplayer players can change their own setting without host permission. Turn advancement uses the incoming player's setting, and reset/reconnect preserves it.

In multiplayer, click your own library to start a private manual search. Filter by name, hold Left Alt to inspect, and drag the chosen card to its destination. Use **Finish search & shuffle** (also available on the top bar after dragging), or **Finish without shuffling** when the effect requires preserving order. Opponents see that you are searching but not your library. For automated search effects, use the effect's eligible-card choices and search box, then confirm; the engine handles placement and shuffling. Finish a manual search before acknowledging its resolved effect.

Manual moves into the library place the card on **top** and preserve the remaining order; they do not shuffle. Hold Left Alt over the card to use **Library bottom** or **Position from top** and **Put in library** (1 = top, 2 = second). These controls work in local and multiplayer games. A search's explicit finish-and-shuffle button and card effects that instruct shuffling still shuffle.

## The table

New turns show a brief **Name's Turn** popup. Successful draws animate a Commander Lab card back from that player's library to their hand, including draws from resolving effects and multiplayer updates. Multiple draws are staggered, opponents' cards stay hidden, and reduced-motion settings replace the flight with a brief fade. Reloading a session does not replay earlier draws.

**Settings > Appearance** includes a color wheel for the app theme. Drag to choose a hue and intensity, use the preset colors, or adjust with the keyboard arrows. The theme applies immediately to menus, controls and table felt, and saves on this computer. **Restore default theme** returns to the original palette. Card artwork, mana colors and gameplay highlights retain their colors.

The app opens on a launch menu with **Local**, **Multiplayer**, **Settings** and **Exit game**. Two generated fantasy panoramas are chosen randomly at startup, pan slowly, and rotate while the menu is open. Settings includes **Animate menu backgrounds** to pause them; the system reduced-motion preference is respected. [Artwork and generation prompts](assets/backgrounds/README.md).

Choose **Local** to set up a 2–4-seat hotseat lobby, or **Multiplayer → Host a room** for LAN play. Other computers use **Multiplayer** to discover the room, or paste its full invite. Each seat imports a deck and readies independently. The host chooses the format and acknowledges each deck's legality warnings before starting. Deck sources include pasted lists, text files and all **39 supplied Commander fixtures**, searchable by commander/theme. These are test fixtures; their appearance in the picker does not mean every card is implemented or the deck is format legal.

Lobby settings include **Regular (London)** mulligans, **Extra free mulligans** (0-20 additional free redraws), and **Gentlemen's rule** (unlimited free redraws). Regular uses one free mulligan in games with three or four players and in Brawl; a two-player non-Brawl game has no free mulligan. Extra adds its configured allowance to that baseline. See the [London mulligan rules](https://magic.wizards.com/en/news/announcements/london-mulligan-2019-06-03).

Starting a lobby, or importing the last deck into a fresh direct table, opens **Verify your starting hand** and pauses gameplay. Choose **Ready** to keep and confirm, or **Mulligan** to redraw according to the lobby rules. A redraw round waits for everyone to decide. Paid mulligans require selecting the cards to bottom before Ready becomes available; the last selected goes bottommost. Hotseat offers player buttons to review each hand; multiplayer shows only your own cards and everyone's readiness. Reload/reconnect preserves progress. Play begins when everyone is ready. **Reset game** repeats verification when all decks are loaded. **Starting hands** on the top bar also starts this flow for an existing table after confirming a clean reset that keeps the decks. Opening-hand decisions cannot be undone. Hold **Left Alt** over cards in this screen or other focused gameplay views to inspect them without changing your selections.

Format presets include Commander, Standard, Standard Brawl, 100-card Brawl, Modern, Freeform and **Two-Headed Giant (manual teams)**. The latter requires manual shared-life, team-turn and team-combat handling. Deck checks cover size, copy limits, commander eligibility/pairing, color identity and cached Scryfall legality; unusual pairing/card exceptions and stale or missing legality data need host review. This is not tournament deck certification.

Choose 2, 3, or 4 active players in the top bar. Changing the count starts a confirmed clean game and preserves unused seats’ decks. **Reset game** also asks for confirmation, returns cards to their owners’ decks and commanders to command zones, shuffles and draws seven, and clears gameplay state while keeping decks and names. Seat-count changes and ordinary manual-table resets can be undone; lobby resets restart opening-hand confirmation.

Four large playmats share one pannable tabletop in clockwise order: seats 1 and 2 above, seats 4 and 3 below. The view starts focused on one seat so its cards and hand stay large. Move the camera across the physical-sized board or zoom out to see the whole table. Every seat has a freely arranged battlefield, a hand, two full-size command-zone slots, and library, graveyard, and exile piles. Only the controlled player's hand is visible; opponents show Commander Lab card backs, including during Alt inspection. Opponents' hand cards cannot be dragged, dropped into another zone, or moved through the inspector. Local play lets you control every active seat: turn handoffs switch the controlled seat, pinned hand, and camera to the next player. Undoing a handoff restores the previous active seat. You can also switch seats to respond or inspect your other hands; the top seat selector and pinned hand selector switch together. The colored outline identifies the seat receiving toolbar actions; the gold dot identifies the active turn. The inspector floats over the view and starts closed, preserving the table's full width.

The tabletop is 6180×3780 logical pixels, with 3000×1800 playmats: 2.5 times the previous area per seat. Cards remain 180×252 logical pixels. **My area**, **Fit seat**, seat shortcuts, and the map frame the entire controlled player's mat above the pinned hand. **Whole table** frames all four seats above the dock. These actions use the dock's current height. Resizing the dock leaves camera position and zoom unchanged; use a view shortcut or switch seats when you want to refit. Zoom in or hold Left Alt for a closer look.

In-game mana and effect choices float over a dimmed, desaturated table with a transparent dialog surface. Scry, library ordering and other card choices show selectable card previews. Combat opens a single central overlay with an Attack / Block / Damage progress indicator, attackers grouped by defender, blockers shown beneath attackers, and projected remaining toughness on the cards. Choose a blocker card and then a highlighted attacker; use **Remove block** to undo an assignment. Confirmation controls stay below the scrolling cards and above the pinned hand.

Cards animate when tapped, untapped, flipped face down/up, or switched to another face. Tapped battlefield cards show a small card-shaped tap-symbol badge beneath their counters and stats; it never blocks card controls. Animations follow received multiplayer updates, survive ordinary redraws, and respect reduced-motion preferences. Reloading or changing seats does not replay them or carry over a previous hand's artwork.

Battlefield cards show power/toughness and separate counter badges over their art. Damage reduces the displayed toughness in red until cleanup; the printed toughness stays unchanged and damage has no counter badge. **Left-click a counter badge to add one; right-click to remove one.** Zero removes the badge, with planeswalker loyalty and battle defense still displaying zero. Hover a card to reveal the **arrow in its top-left corner**. Click it to open **Card actions**, then **Counters** to add the first counter or a new type using common presets or a custom name. The arrow also appears on keyboard focus and works in the enlarged Alt view. Menu and counter clicks do not tap or drag the card. Creature values start from the active face's printed stats; power/toughness counters adjust them automatically. Use the Alt inspector's **Base power / Base toughness** controls for variable abilities or other effects. Other counter badges show up to four types; planeswalker loyalty always has its own badge at the bottom right.

Planeswalkers have **+N**, **−N**, **0**, and **X** ability buttons over their printed costs, on the battlefield and in the enlarged Alt view. Clicking pays loyalty and puts the ability on the stack; X costs ask for a value, and costs exceeding available loyalty are rejected. Each planeswalker normally gets **one loyalty activation per turn**, shared by its printed and granted abilities. Used buttons dim and reject further activations. Usage survives reloads, rearrangement, changes of control, and loyalty-counter edits; a new turn renews the allowance. Leaving and reentering the battlefield starts a fresh permanent. Cancelling or failing payment does not consume an activation. Hold Alt while moving to an enlarged control; releasing Alt over a control keeps it accessible. Placement detects printed shields or retro cost text where possible, with a fallback for unfamiliar frames. **Shift-drag a printed ability button** to adjust alignment; adjustments save with the card and support Undo.

Battlefield effects supply granted abilities through the same ability and payment system. For example, Ichormoon Gauntlet's quoted loyalty abilities appear in a separate panel on eligible planeswalkers, labeled with their granting source; they disappear when the source leaves, becomes face down, or no longer applies. Printed artwork alignment stays unchanged. A granted ability already activated remains on the stack if its source leaves. Proliferate uses the existing counter-choice flow; other effects, including extra turns, remain manual.

`ability-effects.mjs` supplies shared grant descriptors with source identity, stable ability keys, recipient selectors, and active Class levels. Mana, ordinary activated abilities, and loyalty consume these descriptors through their existing payment/stack paths. Supported selectors include controlled types, other/nonland permanents, counter-qualified creatures, and attached permanents. New supported effects can extend this provider and the action resolvers without card-name branches or changes to printed Oracle text.

Extra-activation permissions are read from rules text rather than card-name exceptions: Oath of Teferi-style static limits use the highest applicable limit; duplicate twice-per-turn effects do not stack. Resolved Chain Veil-style additional permissions add activations for the current turn, including for planeswalkers entering later. **Loyalty activations** in Card actions or the Alt inspector shows usage and lets you record extra activations from other resolved effects. For an enchanted-planeswalker permission, use that aura's Loyalty activations settings to choose its attachment; Class permissions apply only at the configured class level. Supported instant-speed loyalty permissions still share the per-turn limit. Targets, other card effects, and unusual permission wording remain manual.

Visible cards show compact keyword pictures along their bottom edge, beside power/toughness. Hover an icon for its name; **+N** lists additional keywords. Battlefield icons follow supported continuous grants, temporary keywords and keyword counters. Hand/command previews show printed active-face abilities, and concealed cards reveal none. The icon set is limited to deathtouch, defender, double strike, first strike, flash, flying, haste, hexproof, indestructible, lifelink, menace, protection, reach, trample, vigilance, ward, prowess, changeling, and affinity. Other mechanics and keyword actions do not produce badges. These indicators describe abilities; they do not add automation for otherwise unsupported rules.

Entering the battlefield initializes printed planeswalker loyalty, battle defense, Saga lore, and explicit self-referencing “enters with … counters” instructions. Modular, graft, fading, vanishing, and sunburst are also recognized. These starting values apply on resolution or a direct move to the battlefield. Rearranging a permanent or moving it between players preserves its values. Leaving the battlefield clears its counters and manual stats; returning initializes fresh values. Saved sessions and Undo preserve existing values.

Variable printed stats, X counters, conditional entering counters, sunburst, and read ahead open an **Entering the battlefield** dialog for your choice. **Set later** leaves a visible reminder and an inspector action to reopen it. This is starting-value assistance: triggers, ongoing board effects, counter multipliers, damage, deaths, and other abilities remain manual. The implementation uses the [official comprehensive rules](https://media.wizards.com/2026/downloads/MagicCompRules%2020260925.txt) for loyalty, defense, Saga lore, and supported keyword defaults.

Drag empty felt, **Space + left-drag**, or **middle-drag** to pan. Scroll to zoom around the pointer; **+ / −** also zoom, and clicking the percentage restores 100%. **Shift-scroll** pans horizontally, or scrolls a hand when the pointer is over it. Arrow keys pan, with Shift for larger movements. **1–4**, the seat buttons, and the overview map jump to a seat. **My area** returns to the controlled seat; **Whole table** or **0** shows all four mats. While carrying a card, pause near a viewport edge to pan toward another seat. Camera position and zoom are remembered locally and do not consume game Undo actions. The overview map hides while the inspector is open to keep the hand unobstructed.

Your **Pinned hand** stays at the bottom of the screen independently of the camera. Hover a card to magnify it and its neighbors like a desktop dock; keyboard focus also enlarges a card. Drag from the dock onto a playmat or stack, or drop a card back into the dock. The dock and table use the same card instances. The pinned player's playmat uses the extra hand space for its battlefield and places both command slots beside the other piles. Other players keep concealed hands on the table. Choose a player using either seat selector; the controlled seat and pinned hand switch together. Hovering over other cards and panning leave your viewpoint unchanged. Use the dock's Draw button for that player, and scroll or use the arrows when the hand grows. Your pinned-player preference is saved locally. Reduced-motion settings disable the enlargement transition.

Resize the dock by dragging its top grip upward/downward to enlarge/shrink cards, its side edges to change width, or its top-right corner to change both. The **− / +** buttons beside the card count also adjust card size. Double-click a resize grip to restore the default size. Focus a grip and use arrow keys to resize or Home to reset. The chosen dimensions save locally and stay within the window; scroll through the hand when larger cards need more room. Resizing does not change cards or game Undo history.

Click **Import deck** and choose a seat, player name, optional commander, and plain-text deck list. Accepts quantities such as `4 Forest`, `4xForest`, and `Forest x4`, comments, and printing annotations. Repeated names, including different capitalization, add their quantities together. Each copy is a separate card that can move, tap, and receive counters independently. Import replaces that seat's zones and stack entries, shuffles its library, and draws up to seven cards. Repeat for the other seats. Deck legality is not enforced. Imports need internet the first time; card data and downloaded artwork are cached locally.

**Load practice table** creates four illustrative decks with visible cards and no internet requirement. These are interface practice pieces, not legal Commander decks or official card text. Loading a practice table preserves the previous table in Undo.

Real deck imports automatically download full card images, including both faces of double-faced cards. Progress appears during import. Repeated copies share one downloaded image but remain separate game pieces. Artwork caches on disk for future imports and saved sessions. If an image download fails, the cards still import and the status bar reports missing artwork. Click **↻ Images** to retry missing images for the current table without replacing cards or resetting gameplay; older cards cached without artwork can also recover this way. The first image download needs internet.

Artwork prefers Scryfall's full-resolution PNG, falling back to large and then normal images when needed. Older normal-size caches upgrade automatically when a session opens; close and reopen the app after installing this code change. If the upgrade is offline, existing artwork remains usable and Images retries it later. The table uses layout zoom instead of scaling a rasterized board layer, so placed cards render from their original image source at the displayed size. Artwork and camera zoom remain separate from card placement and saved game state.

Supported deck actions include Equipment/Aura attachment and search, linked-exile Vehicles with crew, Cat combat effects and armor choices, attack-trigger multipliers, Myriad, goad, foreign free casts, sacrifice follow-up modes and delegated blocking. Simultaneous triggers can be ordered before passing priority; prompted choices survive reload. Fynn adds two-creature damage/fight targets, Bloodrush from hand, activated mode selection and saved repeated proliferate choices. Ten poison, zero life or 21 damage from one commander eliminate a player after resolution; their deck is retained privately for reset. Brawl omits the Commander-damage rule; team loss rules remain manual in Two-Headed Giant. Exact coverage and remaining mechanics are recorded in the deck checklist.

## Controllers

Open **Settings ? Controller** for saved button/stick bindings, device selection, deadzone and speed controls. The starting layout provides a virtual pointer, camera movement, card inspection/placement and menu navigation. Draw, priority passing and other table actions can also be mapped. See [controller controls and setup](docs/controller.md).

## Multiplayer

Open **Multiplayer** to host the current 2/3/4-player table or join by address and room code. To test two clients on this computer, run `npm.cmd start` and `npm.cmd run start:player2` in separate terminals, then host in the first window and join Player 2 at `ws://127.0.0.1:32109` using its room code. Each player keeps local card artwork and controls their assigned seat. Shared actions synchronize the board, stack, mana, combat and turns; private hands and libraries are filtered before sending. Reconnects recover current state, and accepted actions are checkpointed by the host. See [multiplayer setup, recovery and packet design](docs/multiplayer.md). The host must stay open and reachable; a public relay and automatic NAT traversal are not included.

## Mana, casting, and responses

The mana tray stays at the top left of the table viewport. Hover a source and press **T**, double-click, or right-click to activate it. A single simple mana ability adds mana immediately. Multiple available abilities open buttons: triomes offer their three colors; Fire-Lit Thicket offers its filter outputs only when floating red/green mana can pay the input; Karn's Bastion offers **Proliferate** alongside colorless mana when its four-mana cost is payable. **Shift+T** taps without activating an ability. A normal corrective untap removes that source's entire unspent output, including bonuses, and restores any mana spent on its activation. If any output was spent or cleared, the corrective untap is blocked. **Untap from resolved effect** leaves floating mana alone; the turn's normal untap step does too. Undo reverses the whole original action. Basic-land reminder parentheses do not count as an additional activation cost.

Each player has a separate saved floating pool. The tray updates with the controlled seat. Left/right-click a mana symbol to add/remove one as a manual correction; **Pool** manages individual lots, snow mana, spending restrictions, and durations. Mana normally empties at every step/phase transition, including manual step selection, Next step, and End turn. Supported live battlefield retention effects preserve appropriate colors or convert lost mana to colorless; explicitly temporary retention expires when the turn ends. These behaviors follow [Comprehensive Rules 106, 118, and 605](https://magic.wizards.com/en/rules).

Affordable spells in your hand and command zone stay bright based on both floating mana and available mana sources (lands, mana rocks, mana creatures, enchantments, and self-sacrificing sources such as Treasures), including color choices, fixing effects and commander tax. Spells without enough eligible available mana are gray. Each player uses their own resources. The preview respects summoning sickness, activation costs, spending restrictions, and one use per source. It leaves permanents and floating mana unchanged; the payment dialog lets you tap sources before confirming the actual payment. Unmodeled output, abilities that use the stack, and costs requiring other permanents, distributed counters, or discarded cards still require activating that source first; the bounded preview does not assume those choices. Click an affordable spell, or drag it to the stack/battlefield, to review payment and **Pay & cast → stack**. The payment dialog has buttons for the colors to spend: left-click adds one, right-click removes one. **Choose manually** clears the selection; **Auto select** finds a valid payment. The header previews floating mana remaining after payment without spending anything until confirmation. Every printed X uses the chosen value, so `{X}{X}` at X=3 costs six. Payments support per-commander tax, hybrid/colorless/snow symbols, and optional Phyrexian life payment, shown only on relevant cards. **Shift-drag** and the inspector's **Move** controls remain explicit manual zone transfers for setup and unusual effects.

Click a land or drag it onto your battlefield to play it during your main phase. One land play is allowed each turn by default; further lands gray out when the allowance is used. Supported additional-land permissions on the battlefield increase the allowance, and simple resolved extra-land spells grant temporary plays. **Lands used / allowed** opens usage and additional-play controls for other resolved effects or corrections. Usage and temporary allowances reset on that player's next turn. Putting a land directly onto the battlefield through a manual effect transfer does not consume a land play.

**Responses: Auto** skips seats without a detected response, considering floating mana, untapped sources, colored activation costs, instants, flash, legal spell targets, and activated abilities. Uncertain conditions retain a response window. **Responses: Prompt** keeps every response window for that player, so its prompts do not depend on hidden-hand availability. **Responses: Pass all** declines every optional response for that player, even if a response is available. It stays enabled until changed in the three-option selector. Required effect choices, combat declarations, and main-phase plays still wait for input. Each player has an independent setting, saved with the session and retained on reset. The tray follows the controlled seat in local hotseat play; each multiplayer client changes only its own setting, without host permission. Use **Respond · control this seat** to switch hands deliberately, or **Pass** to decline. After consecutive passes, the top spell or ability resolves. Supported instants/sorceries follow their instructions in order and then go to the graveyard; a spell stays on the stack while its resolution choices are pending. Fixed ritual mana and planeswalker mana production happen on resolution. Unsupported instructions require explicit manual resolution.

The cast dialog asks for simple “choose one” modes before spending mana. Use **Choose targets on table** to close the dialog, click highlighted cards or player badges, then review payment. Multiple targets use **Confirm targets**; divided damage uses left/right clicks to add/remove one damage per target. Invalid targets are dimmed. Targeted abilities use the same board picker. A brief public popup shows the played card, selected targets and connecting arrows. Use its **Pass** button or choose response spells, mana sources and abilities directly there; casting no longer opens the stack panel automatically. In local hotseat play, **Respond - control this seat** switches to the player with priority. Shared tables show only your own response choices and wait for other players. The popup follows the top entry and returns to the underlying spell after a response resolves, including after reloading. Those choices appear on the stack while opponents respond. Targets are checked again on resolution; if every target has become illegal, the spell does nothing, including any attached draw instruction. Shared effects now include poison counters followed by draws, life changes, scry with top/bottom ordering, X draws, and targeted damage/removal. Real Scryfall regressions include Prologue to Phyresis, Infectious Inquiry, Swords to Plowshares, Path to Exile, Generous Gift, Chaos Warp and Boros Charm. See the [Oracle engine contract and remaining work](docs/oracle-engine.md) and [deck checklist](docs/commander-deck-checklist.md) for scope.

During declare attackers, click a creature and then its highlighted defending player or planeswalker. The combat overlay groups your attackers by defender; defending seats see only their incoming groups. To block from the overlay, select a blocker and then an incoming attacker. Confirm declarations and review projected damage before applying it. Confirming zero attackers skips blockers and damage and finishes the empty combat, including in **Responses: Prompt**. Pending effects still finish first, and scheduled extra combats remain in the turn.

Extra-combat effects use a saved phase schedule. Aurelia's first attack each turn untaps creatures when its trigger resolves and adds a fresh combat before the scheduled main phase. Karlach's first-combat trigger and Relentless Assault/Aggravated Assault use the same phase and untap handlers. Additional combats get new attackers/blockers/damage decisions while preserving the active turn, land usage, marked damage and effect durations. The step display marks additional phases as **Extra**. Moraug's delayed untaps, exert, rebound/flashback and the other scoped Aurelia checklist actions are verified; unrecognized Oracle instructions retain manual resolution.

Common unconditional mana doublers/triplers, extra-mana triggers, granted creature tap abilities, and retention text are detected from face-up battlefield cards. Multiple replacement multipliers combine; triggered extra mana stays separate. Use **Rules**, or a card's **Mana rules** action, to configure a chosen color, an aura's attached land, or a custom multiplier/bonus/retention rule for conditional or unusual effects. These overrides are saved and undoable. This is bounded rules assistance, not a complete Oracle interpreter.

Exotic Orchard and Fellwar Stone restrict their color buttons to colors opponents' lands could produce; your own lands do not supply colors for them. Reflecting Pool looks at your own lands and can include colorless. Tapped state and activation costs do not remove possible types, while circular references alone do not create colors. If no eligible colors exist, no mana choices appear. Variable outputs whose amounts the app cannot determine still require manual handling.

Additive basic land types are read from live battlefield effects. Dryad of the Ilysian Grove and Prismatic Omen give your lands five single-mana W/U/B/R/G buttons while preserving their existing abilities. Text such as “Each land is a Forest in addition to its other land types” uses the same provider. Added types apply to mana bonuses and possible-color queries, follow the source's controller, and disappear when the source leaves; they do not make nonbasic lands basic. This follows the [Dryad release notes](https://magic.wizards.com/en/news/feature/theros-beyond-death-release-notes-2020-01-10).
Equivalent mana choices share a button: Dryad plus Chromatic Lantern still shows one W/U/B/R/G set. Choices with different activation costs, damage, or other effects remain separate.

Shock lands prompt on entry: pay the printed life amount to avoid their tapped-entry condition, or enter tapped without paying. The payment updates the entering controller's life and persists across reloads; a fresh entry asks again. Pain-land mana abilities apply their printed fixed damage to you once per activation, even when mana is multiplied. Explicit numeric activation life costs are paid automatically when affordable. Corrective mana untaps restore that activation's life loss along with its unspent mana; untapping through a resolved effect does not. These are shared rules-text handlers. Additional damage patterns and replacement effects need manual handling unless covered in the checklist.

Tapped-entry conditions use the entering controller's existing battlefield. Check lands recognize live Forest/Island/etc. subtypes, including types granted by Dryad or Prismatic Omen. Chromatic Lantern's mana abilities do not add land types, and Dryad does not add the Basic supertype. The entering land cannot count itself. Shared checks also handle fast/slow land counts, basic-land counts, legendary-creature/commander requirements and opponent-count conditions. Unconditional tapped entries and supported battlefield replacements apply to other permanent types too. A search that specifies tapped entry still applies even if a shock-land payment is accepted. Conditions requiring unsupported choices, such as revealing a card from hand, show an explicit manual confirmation and block further actions until confirmed. Full continuous-effect layering and arbitrary entry replacements remain unfinished. See [the rules reference](https://magic.wizards.com/en/rules), especially 614.12.

Boros Garrison and similarly worded bounce lands enter tapped and put their land-return trigger on the stack. Choose a land you control on resolution, including the bounce land itself; it returns to its owner's hand. Wind-Scarred Crag's entry trigger gains life on resolution. These are the first verified entry actions in Aurelia's ongoing deck audit.

Proliferate activations pay their costs and use the stack. On resolution, select any eligible permanents and players; each chosen permanent receives one additional counter of every existing kind, and chosen players receive one additional poison counter. Choosing none is allowed. Other player counter types and replacement effects remain manual.

## Manual controls

- Drag a card to a battlefield, hand, command zone, library, graveyard, or exile pile, including another seat's zones. Drag within a battlefield to arrange permanents freely. Placement remains accurate while zoomed and saves with the session.
- Hold **Left Alt** over a card to inspect it and use its controls. The inspector moves cards to any seat/zone, places them on top of the library, and adjusts named counters. Commanders stay face up and cannot be flipped; other double-faced cards can use **Flip card face**.
- Hover a battlefield card and double-click, right-click, or press **T** to tap or untap. **F** turns a hovered card face down or up, except commanders, graveyard, exile, and opponents' hands. Moving away clears selection.
- Click a pile to browse it. Libraries display in top-to-bottom order, left to right. Click a card to inspect it or drag it onto the table. Normal library moves put cards on the bottom; **Library top** puts them on top.
- Open the **Stack** tab and drop a card there, or use the inspector's Move control. Hover **Inspector** while dragging to reveal the stack, or hover the Stack tab in the open panel. Resolve or counter the top entry manually. Turn advancement waits until the stack is clear.
- The selected seat receives **Draw**, **Untap all**, **Shuffle**, **Redraw 7**, and **Token** actions. Each playmat also has its own Draw button. Redraw 7 is a practice tool; apply London mulligan bottoming manually.
- Use the +/- controls to change life. Click a life total to edit player name, life, poison, separate cast counts for each commander, and commander damage received from each seat.
- **Next step**, direct step buttons, and **End turn** move the turn marker manually. **Auto untap / draw** is off by default. When enabled, advancing into Untap untaps the active battlefield, advancing into Draw draws a card, and End turn untaps the next player's battlefield. Direct step selection always moves only the marker. All four seats draw on turn one if automation is enabled.
- **Undo** or **Ctrl+Z / Cmd+Z** restores the previous table action, including resets and imports. Up to 60 actions are kept for the current app session.

## Saves and imports

Game state saves locally after table actions. **Export** downloads a JSON session backup; **Load** restores one. Artwork is omitted from JSON to keep sessions compact and restored from the card cache. If local storage is full or unavailable, the status bar asks you to export. Version 1 sessions from the earlier interface remain compatible; legacy pixel positions are adapted to the new battlefield.

Scryfall lookups happen in the Electron main process through a shared serialized queue, with at least one second between metadata requests. At most 75 uncached names are requested per collection batch; artwork downloads remain separate. On HTTP 429, the queue pauses for at least 60 seconds, honors longer Retry-After values, retries once, then stops on a repeated rate limit. Imports and saved-session artwork restoration use the same cache path. Only one desktop instance runs at a time. The renderer retains context isolation, sandboxing, disabled Node integration, and a local-only content security policy.

### Creating functional token copies

Open a battlefield card's arrow menu and choose **Create token copy**. Choose the number of copies; enable **Not legendary** only when the effect specifies that exception. The **Token** dialog also lets you copy an opponent's public permanent. Copies retain artwork, printed characteristics and abilities, with independent counters, tapping and activation history. Generic imported **Copy** markers are not substitutes for choosing the actual source.

Copied entry counters use the same replacement choices as permanent spells. Doubling Season doubles token quantities, then each token's entering counters are handled separately. These choices survive saves and multiplayer reconnects. Unsupported special copy instructions, including Spark Double's as-enters choice and Cursed Mirror's temporary copying, remain listed in the [playtest audit](docs/playtest-deck-audit.md).

## Scope

This is a local 2D tabletop inspired by physical playmats, with no 3D physics. Optional WebSocket multiplayer runs an authoritative table in the host app while each desktop renders and caches artwork locally. The engine now assists combat declarations, summoning sickness, damage previews, first/double strike, marked damage and cleanup, common keywords, death handling and supported replacements. Ownership is retained separately from the controlling seat for death destinations and resets. Supported Oracle effects use shared handlers for costs, targets, choices, searches, equipment, temporary bonuses and triggers; the deck checklist states exactly what has been verified. Unrecognized triggered effects require explicit manual resolution. Extra turns, many other card-specific mechanics and player elimination remain unfinished. Do not treat sessions as automated win-rate simulations.

In **Responses: Auto**, empty upkeep, combat and other steps pass when no legal action is found. Every player's **precombat main** always waits for a human decision, including after the last affordable action; use **Next step** or **End turn** to proceed. Automatic passing cannot consume another player's entire turn. Required untaps/draws, postcombat main actions, trigger and entry choices, attacker/blocker declarations, damage verification and cleanup discards also retain a stop. Untapped mana sources count when checking possible actions; the check does not tap them or spend real mana. Unknown permissions conservatively retain a window. **Responses: Prompt** holds its player's windows for manual play and privacy; other players retain their own mode.
